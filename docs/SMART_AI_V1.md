# SMART AI V1\n\nSMART AI is the first-party intelligence layer of SMART TIME. In V1 the runtime core is keyless and can answer common app-data questions without calling Gemini or another external LLM.\n\n## Boundaries\n\n- App-data questions use SMART TIME context only.\n- Sensitive fields such as passwords, PINs, tokens, API keys, sessions and vault data are filtered before intelligence processing.\n- Calculations are performed by the SMART TIME data layer; the conversational layer explains the calculated result.\n- External news, weather, sports, markets, maps and web search are separate services and are not required for SMART AI.\n- Data-changing actions remain confirmation-gated.\n\n## Runtime pipeline\n\nUser message -> SMART AI Core -> intent/period detection -> minimal SMART TIME data -> response/action.\n\nThe current V1 response engine is deterministic (rules) so the application can run without an AI API key. A locally hosted or fine-tuned model can be added later behind the same core contract.\n\n## Training target\n\nThe future model should learn SMART TIME terminology, Egyptian Arabic conversation style, explanations, summaries, clarification behavior, and safe tool usage. Training examples must teach behavior, not store real customer records.\n\n## Data contract\n\nThe model receives structured, sanitized app summaries. It must never invent totals, dates, IDs or records. Database reads and writes remain application-owned.\n\n## Next phases\n\n1. Expand intent and period coverage.\n2. Add server-side data tools so the browser does not send broad context.\n3. Run the local inference adapter with a SMART TIME-specific model.\n4. Build a de-identified SMART TIME instruction dataset.\n5. Fine-tune with LoRA/QLoRA and evaluate on held-out SMART TIME conversations.\n6. Add a first-party TTS provider/engine for consistent SMART TIME voices; browser speech remains the current fallback.\n
